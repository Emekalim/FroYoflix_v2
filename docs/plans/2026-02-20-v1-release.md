# v1.0.0 Versioning & Release Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship FroYo v1.0.0 by bumping versions, fixing the CI release pipeline, and cutting the first tag.

**Architecture:** Two `package.json` files drive all version numbers — `electron/package.json` for the Electron app and GitHub Release tag, `capacitor/package.json` for the Android APK (read by `build.gradle`). A tag push (`v*.*.*`) triggers `main.yml` which builds Electron on all platforms and publishes a GitHub Release; `android.yml` chains off that success to sign and attach the APK.

**Tech Stack:** electron-builder (Electron packaging + GitHub publish), GitHub Actions, pnpm, Gradle (Android)

### Task 2: Fix the CI release workflow trigger and pnpm bug

**Files:**
- Modify: `.github/workflows/main.yml`

**Context:** The workflow currently fires on push to `main`/`master` (branches that don't exist on this repo). It also incorrectly calls `npm run publish` despite installing with `pnpm`. Both bugs mean it has never run successfully.

**Step 1: Replace the trigger block**

In `.github/workflows/main.yml`, find and replace the `on:` block:

```yaml
# BEFORE
on:
  workflow_dispatch:  # Allows manual triggering
  push:
    branches:
      - 'main'
      - 'master'
    paths-ignore:
      - '**.md'
      - '**.yml'
```

Replace with:
```yaml
# AFTER
on:
  workflow_dispatch:  # Allows manual triggering
  push:
    tags:
      - 'v*.*.*'
```

**Step 2: Fix npm → pnpm (3 occurrences)**

Find all three `npm run publish` lines in the file (one per job: `release-windows`, `release-linux`, `release-macos`). Change each:
```yaml
# BEFORE
          npm run publish
```
To:
```yaml
# AFTER
          pnpm run publish
```

There are exactly 3 occurrences — one in each job's "Build and Publish" step.

**Step 3: Verify the YAML is valid**

Run:
```bash
python3 -c "import yaml; yaml.safe_load(open('.github/workflows/main.yml'))" && echo "YAML valid"
```
Expected: `YAML valid`

**Step 4: Verify the trigger section looks correct**

Run:
```bash
grep -A 5 "^on:" .github/workflows/main.yml
```
Expected output:
```yaml
on:
  workflow_dispatch:  # Allows manual triggering
  push:
    tags:
      - 'v*.*.*'
```

**Step 5: Verify pnpm is used everywhere**

Run:
```bash
grep "npm run publish" .github/workflows/main.yml
```
Expected: no output (zero matches).

**Step 6: Commit**

```bash

### Task 4: Add release runbook

**Files:**
- Create: `docs/releasing.md`

**Step 1: Create the file**

Create `docs/releasing.md` with this content:

```markdown
# Release Process

## How to cut a release

Releases are triggered by pushing a version tag. CI builds Electron (Windows/Linux/macOS) and Android automatically.

### Steps

1. **Bump versions** in both `electron/package.json` and `capacitor/package.json`
2. **Update `CHANGELOG.md`** — change `[Unreleased]` to `[vX.Y.Z] - YYYY-MM-DD`
3. **Commit and push** to `stable_base`

```bash
git add electron/package.json capacitor/package.json CHANGELOG.md
git commit -m "chore: bump version to X.Y.Z"
git push origin stable_base
```

4. **Tag the commit and push the tag**

```bash
git tag vX.Y.Z
git push origin vX.Y.Z
```

CI fires automatically. Monitor at: https://github.com/Emekalim/FroYoflix_v2/actions

---

## Version locations

| File | Purpose |
|------|---------|
| `electron/package.json` | Electron app version + GitHub Release tag |
| `capacitor/package.json` | Android APK version (read by `build.gradle`) |

Keep both in sync — they should always have the same version number.

---

## What CI produces

| Artifact | Platform |
|----------|----------|
| `windows-FroYo-vX.Y.Z.exe` | Windows installer |
| `windows-FroYo-vX.Y.Z-portable.exe` | Windows portable |
| `linux-FroYo-vX.Y.Z.AppImage` | Linux |
| `linux-FroYo-vX.Y.Z.deb` | Debian/Ubuntu |
| `mac-FroYo-vX.Y.Z.dmg` | macOS |
| `android-FroYo-vX.Y.Z.apk` | Android (signed) |
| `latest.yml` | Electron auto-updater manifest |
| `latest-android.yml` | Android auto-updater manifest |

---

## Semver guide

- `vX.0.0` — Major: breaking changes or significant new features
- `vX.Y.0` — Minor: new features, backwards compatible
- `vX.Y.Z` — Patch: bug fixes only
```

**Step 2: Commit**

```bash
git add docs/releasing.md
git commit -m "docs: add release runbook"
```

### Task 5: Cut v1.0.0

**Context:** All the prerequisite changes are committed. This task pushes them to `stable_base` and creates the release tag.

**Step 1: Confirm you are on the right branch**

Run:
```bash
git branch --show-current
```
Expected: the working branch (e.g. `froyo_rename` or `docs/cleanup` merge result). If you're not on `stable_base` yet, merge your branch first.

**Step 2: Push current branch to stable_base**

```bash
git push origin HEAD:stable_base
```

Or if already on `stable_base`:
```bash
git push origin stable_base
```

**Step 3: Verify the version commits are included**

```bash
git log --oneline -5
```
Confirm `chore: bump version to 1.0.0` and the CI fix commits are present.

**Step 4: Create the tag**

```bash
git tag v1.0.0
```

**Step 5: Push the tag**

```bash
git push origin v1.0.0
```

**Step 6: Verify CI triggered**

Go to: https://github.com/Emekalim/FroYoflix_v2/actions

The "Electron Build and Release" workflow should appear as running. Once it completes successfully, "Android Build" will start automatically.

**Step 7: Verify the GitHub Release**

Go to: https://github.com/Emekalim/FroYoflix_v2/releases

A `v1.0.0` release should appear with all platform artifacts attached.
